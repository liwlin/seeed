# Part 2 · Mission Center V0.4 网页预览版

入口：[Part2_AI_Guardian_MissionCenter_V0.4.html](Part2_AI_Guardian_MissionCenter_V0.4.html)

课程入口：[Part 2课程材料](../../AI碉楼守护者/Part2_建造AI碉楼守护者/README.md)

页面保持单HTML，图片与脚本均已内嵌。双击即可打开任务与Prompt编辑界面。任务操作区为主体，地图在侧栏辅助导航；手机先任务和Prompt，再显示进度。

网页教学提示对应已公开的Part2课程V1.0统一版（40页课件、285分钟净教学），工具版本仍为V0.4。[教学资料索引](../../AI碉楼守护者/Part2_建造AI碉楼守护者/教学资料索引.md)提供PPT、教师讲义、任务册、记录单、十关任务卡与配图；开发文档、制作数据和历史备份保留本地。

围绕“分工协作，建造碉楼守护者”：方案设计员制定目标和规则，硬件验证员操作真板、记录现象与复测结果；每关结束交换角色。

## 步骤切换

任务、线索、Prompt、CodeCraft、真机、反馈、通关七个步骤均可直接点击切换。切换前保存当前填写的内容，支持返回修改和键盘Enter操作。选择步骤仅改变当前视图，不会自动领取徽章或解锁下一关；教学仍按任务流程和真实证据验收。

## LLM API 设置

点击顶部菜单栏的“LLM API 设置”，填写Base URL、模型名称和API Key。默认使用 DeepSeek 的 OpenAI 兼容 Chat Completions 协议，默认地址为 `https://api.deepseek.com`。可以填写包含版本前缀的Base URL，也可以直接填写完整 `/chat/completions` 地址。模型字段请填写账号当前可用的模型。

API Key只在当前页面会话内保留，刷新后重新填写。页面仅保存非敏感的接口地址、模型和JSON模式选项，日志和导出不包含Key。请求只在学员点击评分或润色时发送。

DeepSeek支持JSON输出模式；若兼容供应商不支持 `response_format`，可在设置中取消“使用JSON输出模式”。接口需要允许浏览器跨域请求；连接失败时检查地址、模型、密钥、网络及CORS。页面不自动重试请求，有45秒超时和取消按钮。

协议说明：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON输出](https://api-docs.deepseek.com/guides/json_mode/)。

## 先评分，再按需润色

1. 在可编辑的Prompt框写自己的要求，或从已填写的任务线索生成草稿。
2. 点击“提示词评分”，阅读各项理由与改进建议。
3. 学员可以自己补充一处再评分，也可以在同一份稿已评分后点击“AI 润色”。
4. 对照原稿、建议稿和修改原因，检查硬件、读数、阈值与规则。
5. 选择采用建议或保留自己的原稿。采用后保留原稿，并要求重新评分；可以恢复原稿。
6. 到CodeCraft生成、编译、烧录，再做真实硬件验证。

编辑当前提示词、切换任务或改变板卡设置会使相应旧评分失效。其他测量字段、规则或图示选择变化未必自动重建现存稿或清除旧分数；修改后应主动核对当前稿并重新评分。请求中的编辑、换关卡或取消会中止当前请求，迟到的结果不会覆盖新稿。M10仍需学员自行写完整需求，AI只针对已有稿评价和润色。

## 评分标准

| 项目 | 满分 | 关注点 |
|---|---:|---|
| 任务目标 | 15 | 当前关卡希望实现什么 |
| 硬件信息 | 15 | 相关板卡、模块和已知版本是否说明 |
| 规则与参数 | 25 | 条件、阈值、时间、状态等是否可理解 |
| 输出要求 | 15 | OLED、LED、蜂鸣器等预期是否可观察 |
| 边界约束 | 10 | 要保留什么、未知项和异常情况 |
| 验证方法 | 20 | 怎样操作真板判断结果 |
| 合计 | 100 | 六项总分由页面重新计算 |

评分根据当前关卡适用性进行，纯输出任务不因没有传感输入而扣分。AI评分只评价表达质量，不是实板验收、学生能力定论或程序正确性证明。

## 现有边界

- 网页不打开串口、不连接开发板、不编译或烧录；CodeCraft负责程序与真实硬件链路。
- 默认字段会在生成草稿或进入下一步时保存；M04亮暗及阈值、M05阈值输入留空，示例只作placeholder。填写本组数值后才能生成控制草稿。光线判断方向依据本组可比较的亮暗记录，未知时保持待确认。
- 网页仍允许空记录领取徽章，教师依据真板结果和V2复测认定完成。
- 反馈草稿依据真实结果类型和CodeCraft错误记录组织，编译/烧录失败不再声称已成功；事实仍须学生核对。
- 教师模式会保留到刷新之后，演示结束需主动退出。
- 评分上下文不会自动读取全部图示选择、实测字段、单位或接口表；把本组已确认信息写进提示词，另由教师核对。
- 网页导出不保证保存实际提交给CodeCraft的V1稿，生成反馈也可能替换当前草稿；另外保存V1/V2原文、工程和真实观察。
- 新任务文字保留既有字段ID与历史进度，旧勾选需按新要求人工复核，不能当作新规则已通过。
- 本次按Part1规则公开V1.0当前教学材料、必要配图与网页工具；真实课堂适配仍需教师确认，开发文档、制作脚本、源数据和历史备份不上传。

本版已做核心单元测试、模拟 API 浏览器流程、1024 种模块组合布局、桌面/手机完整显示与 SVG 导出检查。发布截图没有使用真实 Key 调用模型；CodeCraft 编译烧录和真实硬件效果仍需在课堂环境验证。

## 当前每关的七步引导

1. 课堂情境、作品预期、方案设计员与硬件验证员动作、本组目标。
2. 本关要观察什么、测量小程序或版本确认、字段含义和实测记录。
3. 模糊/清晰表达对照，编辑、评分、自行改进、按需润色的实际入口。
4. CodeCraft生成、编译、烧录的区别和完整错误记录。
5. 具体动作、可观察的预期和V1实物记录。
6. 结果分类、单项改动、生成真实反馈和同动作复测。
7. 本组证据汇总、反思问题、保存工程与日志、下一关为什么需要。

V2实验在第6步完成后回填网页既有复测栏（当前仍位于第5步区域），栏位位置不改变课程顺序。M05基础固定光线＋声音＋LED，覆盖明亮/暗光与安静/大声四种组合；M06按恢复环境、按键确认、新异常再触发测试，M07基础不沿用锁存。M08先确认版本与单位，M09先确认XYZ基线；M10功能模块至少三个，主控与USB不计数。数据和阈值示例不代表本组实测。

## 硬件实物与板内接线图

任务、线索和CodeCraft步骤可直接查看对应模块，其他步骤用标题旁“本关硬件图”打开。支持照片高亮、器件特写、全部已选模块同时显示的接线图、放大、下载 SVG 和调整图示清单。主板固定比例并居中，元件自动在上下左右排布；默认适应画布完整显示，原尺寸模式可滚动查看细节。选择只影响展示，不改变程序、不读取或控制硬件。

整板模块已通过PCB连接，课堂只需USB数据线。新旧温湿度接口必须区分：旧DHT11为D3，新DHT20为I²C；版本未确定时不猜接线。主照片为官方新版实拍，旧版参考是官方布局示意，不能当作旧版照片。M10默认不选系统，由学员自主选择后更新图。

图已内嵌在单HTML中，不依赖额外在线图片。连接类型与引脚见[接口参考](../../AI碉楼守护者/Part2_建造AI碉楼守护者/教学素材/硬件图/传感器接口与引脚说明.md)，三张实际界面见[Part2 入口](../../AI碉楼守护者/Part2_建造AI碉楼守护者/README.md)。
